# InoProShop Engineering MCP

通过 DeepSeek Harness（DSH）调用本地 InoProShop，完成受管理的离线工程读取、有限修改、编译、保存重开和版本对比。

**main 当前提供0.11.0 候选版，十九项 MCP 工具，契约1.0.0。** 实测环境为 Windows、InoProShop 1.9.1.6；既有桌面证据使用DSH 0.2.0-rc.2，枚举CLI验收使用0.2.1-rc.5，两类证据分别记录。源码仓库现已公开，可按[入门文档](docs/getting-started.md)直接从main获取0.11.0；当前仍是限定范围的离线试用版，不是正式v1.0。

精确 Application 的 `library_inspect` 由0.10.0引入，现有工具调用继续兼容。**DSH库查询工具只读流程通过；答复简洁展示及部分措辞未完全遵循，原文和勘误保留。** 库引用、当前解析原文与独立加载状态分别表达，不把工具流程通过写成回答质量全部通过。[库查询契约与边界](docs/library-inspect.md)。

0.11.0已将`codex/enum-dut-create`的普通枚举能力并入main：扩展原`declaration_create`，不新增工具，仍十九项。DSH命令行实际加载、枚举创建与PROGRAM接入离线闭环已复核通过；辅助终端失败、预检首败和答复展示勘误另存，不称为桌面交互或整体回答质量通过。[枚举范围与验证边界](docs/enum-dut.md)。

## 支持范围

| 类别 | 工具 |
| --- | --- |
| 环境、状态和操作证据 | environment_inspect、session_status、operation_status |
| 工程副本、登记和切换 | project_open_copy、project_list、project_activate |
| 源码定位与读取 | object_list、object_read、project_search |
| 原生结构、设备与任务只读 | project_structure、device_inspect、task_inspect、library_inspect |
| 限定创建和修改 | pou_create、declaration_create、code_apply_change |
| 离线工程闭环 | project_build、project_save |
| 可信工程快照对比 | project_compare |

main源码范围为既有支持的ST POU声明/实现、Application根GVL、结构体及普通枚举DUT声明。枚举objectType=enum，使用原生Enumeration工厂，成员各显式十进制整数-32768..32767且名称和值不重复，不开放属性/显式基类型/复杂表达式。pou_create在根节点支持FUNCTION_BLOCK、PROGRAM、显式DINT/BOOL/INT/REAL/TIME返回值的FUNCTION；原功能块参数兼容，GVL、结构体及普通枚举由declaration_create创建。PROGRAM不自动加入任务，需按授权接入现有程序并编译。[参数与边界](docs/getting-started.md#创建-st-pou)。对比覆盖所支持源码及task_inspect实际可读字段和调用顺序，不包含设备参数、I/O映射及其他非ST内容。

保留单活动工程、串行队列、精确Application/对象定位、检查点、版本冲突校验、去重、写后读回和unknown冻结。源工程与工作副本分别保存，同名对象不静默覆盖。只读IDE可能写.opt等附属文件，工程哈希不变不代表目录所有文件不变。

[修改前工作副本基线与交付后比较](docs/post-change-baseline-compare.md)已接入支持的Application日常修改：先采可信基线，再按原闭环修改/编译/保存重开，最后以同一副本的最终快照比较；默认不拿原交付源代替本轮基线。2026-11-02真实DSH修改闭环及比较已复核通过，当轮保持0.7.0和十八工具，无新增工程执行代码。DSH 0.2.0-rc.2客户端需使用模板的 `maxInstructionBytes: 65536`；可用 `npm run check:instructions` 静态核对UTF-8大小，详见[接入上限说明](docs/getting-started.md#指令大小与连接失败)。
