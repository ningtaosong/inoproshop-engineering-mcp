## CLI 流程与原答复

一次用户任务产生 45 次工具调用，含一次替换、一次显式保存和两次编译。模型在等待中查询原操作，共调用 `operation_status` 20 次，运行时给出三次重复查询提醒。模型也做了额外的只读查询。该任务无参数拒绝、冲突或重复写入。原答复中的顺序、中文备注、四个定义和编译计数与工程证据一致，工程链接未做点击验收。

会话 `session-8c7991aa-3d12-49bf-9acc-5d7f04e704ed` 的正式连接取得 0.33.0、完整 36 项工具，并在该连接上调用了 `task_call_replace`。初始化正文含客户端标题计 62,879 字节，上限 65,536。用户消息、模型调用与结果、最终助手正文按各自消息身份核对。仅探测子进程的连接另行记录。

## 离线验证和首次失败

- `8a6f334d5e64af6a3af0c274b4b8ef4aa799af66` 的独立临时目录 Node 完整回归为 503/503，Python 完整回归为 233/233。随后只修订模型工作指令和使用说明。最终受验提交通过构建、类型检查、原契约比较、指令大小检查及定向 Node 37/37、Python 19/19。各组独立计数。
- 直接编辑与旧副本的故障由服务夹具及生产桥接替身验证，覆盖写前拒绝、原生改名后或设置备注时发生异常、重开证据不符、请求去重和冻结。真实 IDE 的两项验收均为正向写入。
- 首次准备启动开发端验收时发现离线回归的子进程，待其退出后才启动。开发端首次读取又因取证脚本假定旧 `task_inspect` 一定返回已解析而停止，当时只完成打开及读取，尚未替换。旧工具对于非空调用备注可同时给出 unresolved 和一个候选。补充工作指令后，在相同磁盘版本上以完整原生行、唯一候选、带版本的定义和写入句柄内复核证明归属。原工具契约保留。
- 离线归档脚本初次处理没有持久化操作号的会话查询时抛出 `KeyError`。修正后读取同一批原始结果，保留首败。
- 收尾时无在办操作或候选服务进程，原登记目录的租约显示 stale，原因为持有进程已退出。四项历史 unknown、隔离账本、原移除现场及日常配置的保全指纹核对通过。日常入口未切换。

本次验收限于离线工程配置。单条移除的原生缺陷、历史 CmpLog、默认环境已知的状态查询性能问题、脚本信任及 Desktop 欢迎页分别保留。实际调度、设备 I/O 和 PLC 运行未验证。
