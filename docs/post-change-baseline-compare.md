# 本轮修改前基线与交付后比较

本功能分支只整合现有Agent工作流程，保持服务0.7.0、十八项MCP工具与旧契约。产品代码、Schema和桥接不变，没有新增服务端强制事务、写入控制器或自动回滚。**指令整合的DSH桌面验收待完成，本轮不合并main。** 既有只读工程对比流程通过是历史结果，不能代替此次整合验收。

## 哪个版本作为基线

对project_compare支持的Application修改、创建及受限修复任务，先查询环境、会话、登记、真实源码，明确目标与保留项。在首次业务写入前调用project_compare：`mode=capture, origin=working-copy`，保留成功采集的原操作引用、工程/Application/路径、版本和覆盖。这是本次修改前基线，包含此前已接受的所有修改。创建/修改工具会自行持久化，不能等到最终project_save才采基线。

普通日常修改不默认使用`registered-source`。只有用户明确要求同原交付工程比较时，才另行采登记源，并明确两份比较的含义。例如当前工作副本已从交付初始5秒改成8秒，这次再改12秒，本轮差异应是8→12；5→12属于同原交付版本的另一次比较，不能冒充本轮差异。数值只作示意，结论须取自真实读取。

基线缺失、失败或不可信时，在首次写入前说明并停止，不能修改后补造。客户端没有project_compare时同样停止本流程；成功capture仍须核对覆盖，缺口使本次要求的保留项无法核对时写入前停止。只读解释不触发写入流程。对象池等不支持目标如实说明不适用，不扩大现有编辑边界；用户明确要求比较而当前不支持时，写入前说明并停止。

## 完整顺序

1. 实际读取，确定本次授权目标、源码初始化设定和保留项。
2. 成功采集当前工作副本作为本轮基线；成功之后才允许首次业务写入。
3. 沿用当前版本校验、检查点、去重、冲突检查和写后读回进行有限修改。
4. 真实编译，保留错误/警告及诊断完整性；工具完成不等于编译通过。
5. 最终保存、关闭重开；依据保存结果和编译适用性判断是否需对保存版本复编。
6. 最终源码全文核对，确认实际交付的工作副本/磁盘版本。
7. 对同一工程、Application和工作副本，以`mode=capture, origin=working-copy`采集最终快照。
8. `mode=compare`内部引用本轮修改前基线及最终采集，按实际nextOffset/expectedVersion取完比较页；必要长变更读同版本详情。

受限修复保留真实首次编译失败、白名单及至多三轮规则，一份本次基线覆盖全部修复，不能通过逐轮改换基线隐藏累计变化。上面的比较也不能替代源码读回、编译或保存重开。

## 如何解释结果

核对源码变化、对象新增/删除和可读任务字段/调用顺序是否全在本次授权内。仅已读取并实际核对一致的内容报告未变；不完整枚举/读取、缺证据和无法比较均不能写成全部核对通过。设备参数、I/O映射和其他非ST内容未覆盖，不把“没有编辑”写成“完整配置已核对一致”。任务周期只是配置，不是扫描耗时。

发现额外变化时，报告已经完成的写入及比较异常，停止后续自动写入并保留现场，不自动回滚、不继续修改掩盖差异，也不为补证据重新执行写入。比较不完整/未完成则如实报告；不能因为写入或编译已成功而将整体检查写成完成。

running查询原操作；unknown/冲突/冻结按原机制处理，不换编号重放、删锁或换目录。Agent停止后续写入不等于服务端新增冻结控制；只有工具真实返回冻结时才能这样报告。

默认答复保留关键改动、实际编译错误和警告及影响、保存重开、本轮差异和覆盖限制，同时给出实际工作副本打开链接与单独完整绝对路径。原始引用、哈希/版本、完整差异和诊断留在内部。初始化设定不等于运行当前值，未做运行观测就不宣称实际计时通过。

## 现有实现核对

本轮是代码阅读结论，不是新增工程实测或重跑回归。

| 实现 | 核对结果 |
| --- | --- |
| [service.ts](../src/service.ts) 的 recordedComparisonSnapshot | 从原成功capture及其原project绑定、完整IPC恢复历史快照；核对登记路径/隔离与原发布版本，不要求基线文件哈希等于当前副本。 |
| [comparison.ts](../src/comparison.ts) 的 captureSnapshot | 使用原采集操作中的工程状态核对历史磁盘哈希、Application和原始只读证据，并重算内容版本。 |

因此现有能力可以比较同一工作副本的修改前历史capture与修改后当前capture，本轮不需改产品代码。[工具Schema](tool-schemas.json)与[唯一工作指令](../instructions/inoproshop-workflow.md)继续为执行依据。

## 手动桌面验收与合并门槛

公开文档使用示例路径，例如`D:\PLC-Test\DualAlarm.project`；维护者的真实本地任务、工程、操作记录、锁及复核ZIP不进入公开仓库。指定测试任务会先实际确认第一路10秒、第二路8秒，再在首写前采基线，只改第二路到12秒并完成上述闭环；不一致即停止，不预写工具结论。

验收时必须从真实对话及操作证据核对：

- 先实际读取前置值，再取得working-copy基线成功，时间顺序早于任何本轮业务写入；没有拿registered-source替代。
- 写入仅限授权内容，编译错误/警告、保存关闭重开、必要复编与最终全文均有真实证据。
- 最终同一副本capture在最终读回/必要复编之后，比较引用准确；实际分页和必要详情已完整取得。
- 唯一预期源码变化是第二路8→12秒，另外三个支持对象及可读任务配置一致，以实际结果为准；设备/I/O未覆盖。不把原交付5秒当本轮起点。
- 不确定/冲突/额外变化时停止自动写入；没有重放或自动回滚；答复简洁且含真实路径/链接、警告和运行未验边界。

本轮只做文档静态检查和独立MCP初始化（版本、工具列表、实际instructions），不执行上述工程任务、不代用户发送消息、不重跑完整回归。检查通过不代表DSH已载入或模型遵循。加载新指令须确认DSH空闲、没有未发送输入或未确认终止的执行，再正常重载；不能确认时保留待办，不强制结束。已受控隔离的历史unknown不因该流程改变。

取得本轮真实桌面验收并复核必要证据后，才能重新核对最新main、处理变化并完成必要复验，再合并及推送main；本轮仅提交/推送功能分支。历史11/12回答质量结论、旧CmpLog警告、隔离unknown与原锁保持，造物场文章不更新。
