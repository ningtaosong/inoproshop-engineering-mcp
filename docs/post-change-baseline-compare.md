# 按需建立基线与比较工程

## 当前使用规则

2026-11-09 起的工作指令调整：普通修改、创建和受限修复默认执行[日常修改闭环](getting-started.md#日常修改闭环)，不自动调用 project_compare，不要求基线或前后比较。缺少比较工具/基线不阻止普通授权修改，不默认追加全工程源码检查。版本与磁盘校验、内部文本 snapshot、检查点、写后读回、编译和保存重开继续保留。

只有用户明确要求比较时执行本页流程。服务仍为 0.16.0 候选版、二十一项工具；不改变 project_compare 接口，不增加服务端事务或自动回滚。直接编辑、身份与登记 v2 语义见[直接编辑说明](direct-project-edit.md)。历史验收保留在下方，不能用旧比较任务通过推定新默认流程已通过模型验收。

## 哪个版本作为基线

用户在写入前要求本轮前后比较时，先确认精确工程/Application、授权范围和覆盖，首次业务写入前调用 project_compare：`mode=capture, origin=current-project`。内部保留成功操作引用、工程/Application/实际路径、版本和覆盖，这是本轮修改前基线。创建/修改工具自身会持久化，不能等到最终 project_save 前才采集。旧副本 `working-copy` 参数保持兼容。

`registered-source` 仅用于用户明确要求同原交付来源比较、且有独立来源的旧副本登记。新直接登记没有不变来源，不支持该 origin；可以使用真实历史快照或明确的另一文件作比较。当前 8 秒改 12 秒的本轮差异是 8→12，与交付版本 5→12 属于不同目的，不能互相替代。数值仅为示例，结论以实际读取为准。

已要求比较而工具缺失、基线失败/不可信或覆盖不足以完成要求时，在写入前说明并停止，不静默省略比较。用户在修改后才提出前后比较且没有可信历史基线时，如实说明无法证明本轮全部差异；不补造、不回滚、不重放写入或另做一次修改来制造基线。两份现存文件的比较须明确版本和目的，不能冒充缺失的历史基线。对象池等不支持范围如实说明；独立只读比较不触发修改、编译或保存。

## 用户要求本轮比较时的顺序

1. 必要读取定位，核对完整对象名、授权范围、原文和当前哈希；需要成员查询时核对真实声明及位置，不使用旧页位置。
2. 成功采集当前指定工程的修改前基线，确认其覆盖满足比较要求后才进行首次业务写入。
3. 按日常流程修改、写后读回、真实编译、保存关闭重开、必要复编及修改对象最终读回，确认编译证据适用于实际交付文件。
4. 对同一工程/Application/实际路径，以 `mode=capture, origin=current-project` 采集最终快照。
5. `mode=compare` 引用两项原成功采集，按实际 nextOffset/expectedVersion 取完比较页；长变更按需读取同版本详情。

受限修复保留真实首次编译失败、白名单及至多三轮规则；要求比较时同一基线覆盖全部修复，不逐轮更换来隐藏累计变化。比较不能替代源码读回、编译或保存重开；内部 expectedSnapshot 仍使用工程操作返回的文本 snapshot，不能拿比较版本代替。

## 如何解释结果

核对源码变化、对象新增/删除和可读任务字段/调用顺序是否全在本次授权内。仅已读取并实际核对一致的内容报告未变；不完整枚举/读取、缺证据和无法比较均不能写成全部核对通过。设备参数、I/O映射和其他非ST内容未覆盖，不把“没有编辑”写成“完整配置已核对一致”。任务周期只是配置，不是扫描耗时。

发现额外变化时，报告已经完成的写入及比较异常，停止后续自动写入并保留现场，不自动回滚、不继续修改掩盖差异，也不为补证据重新执行写入。比较不完整/未完成则如实报告；不能因为写入或编译已成功而将整体检查写成完成。

running查询原操作；unknown/冲突/冻结按原机制处理，不换编号重放、删锁或换目录。Agent停止后续写入不等于服务端新增冻结控制；只有工具真实返回冻结时才能这样报告。

执行比较后，在日常修改结果之外报告真实差异和覆盖限制，同时给出实际工程打开链接与独立完整绝对路径。未要求比较时不追加“比较待验”任务，也不声称未检查的对象或配置一致。原始引用、哈希/版本、完整差异和诊断留在内部。初始化设定不等于运行当前值。

公开文档使用示例路径，例如`D:\PLC-Test\DualAlarm.project`；维护者的真实本地任务、工程、操作记录、锁及复核ZIP不进入公开仓库。指定测试任务会先实际确认第一路10秒、第二路8秒，再在首写前采基线，只改第二路到12秒并完成上述闭环；不一致即停止，不预写工具结论。

验收时必须从真实对话及操作证据核对：

- 先实际读取前置值，再取得working-copy基线成功，时间顺序早于任何本轮业务写入；没有拿registered-source替代。
- 写入仅限授权内容，编译错误/警告、保存关闭重开、必要复编与最终全文均有真实证据。
- 最终同一副本capture在最终读回/必要复编之后，比较引用准确；实际分页和必要详情已完整取得。
- 唯一预期源码变化是第二路8→12秒，另外三个支持对象及可读任务配置一致，以实际结果为准；设备/I/O未覆盖。不把原交付5秒当本轮起点。
- 不确定/冲突/额外变化时停止自动写入；没有重放或自动回滚；答复简洁且含真实路径/链接、警告和运行未验边界。
