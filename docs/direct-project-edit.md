# 直接编辑指定工程（0.16.0 候选）

main 提供新增的 `project_open`，共二十一项工具。默认打开指定 `.project`，修改、保存及重开均在同一文件；没有新的业务工作副本。

## 使用

提供工程绝对路径、修改目标、当前预期值和保留项。例如：

> 直接打开 D:\PLC-Test\Alarm.project。先读取并确认第二路初始化为 5 秒，采集修改前基线，只改为 8 秒。保留其他源码和任务，编译、保存关闭重开、必要复编、最终读回和比较。出现冲突或未知停止；不连接 PLC。

Agent 先查询环境、会话和登记，用 `project_open({requestId,projectPath,applicationId?})` 打开文件。多应用时使用真实候选选择，不让用户填写 GUID。输出链接指向工具实际确认的工程路径；Windows 短路径会解析为同一文件的真实路径，不代表创建副本。

直接编辑要求工程在外部 IDE 中已保存关闭。服务不会附着到任意已有 IDE、接管未保存内容或关闭别人的工程。

## 身份与旧调用

- 新直接登记标记 `storageMode=direct, editMode=direct`，`directPath` 固定解析后的真实路径。为兼容记录读取，`sourcePath/workingPath` 均描述这一个文件；这不是跳过校验：每次派发额外核对实际路径、当前 diskHash、原生占用和原结果证据。
- `sourceHash` 仅记录首次登记时的内容。修改后的当前版本更新 `diskHash`，不要求当前文件永远等于首次登记哈希。
- 显式打开旧副本路径时复用旧 projectId、来源记录和实际文件，仅启用直接编辑保护。显式打开旧来源路径时另建直接身份，绝不跳转到旧副本。
- 旧 `project_open_copy` 仍只查找旧副本登记，或创建新的独立副本；它不会因为新直接登记而开始覆盖来源。没有批量迁移或删除旧工程。
- 保存后可重新打开同一登记文件；若文件在外部改变，打开不会自动接受新版本。文件别名或身份歧义明确拒绝。

首次成功启用直接编辑时，登记容器格式升级为 v2，原有记录字段和工程文件保留。0.15.0 及更早二进制不能识别该格式，必须停止读取，而不能把直接工程误当副本。因此同一数据目录的 DSH/Codex 服务入口都应使用 0.16.0 或更高兼容版本后再移交；不要将 v2 手工降回 v1，或删除登记来绕过。旧 MCP 接口兼容不等于旧服务二进制可以读取新登记。

## 快照、保护与保存

修改前和最终版本均使用 `project_compare(mode=capture, origin=current-project)`。比较引用两项原成功操作，历史基线按当时记录核对；当前文件变化不会抹去历史基线，但最终目标快照必须匹配当前交付文件。

旧 `working-copy` 参数仍可用，直接模式按当前工程解释；旧副本的 `registered-source` 语义保留。新直接登记没有独立不变来源，`registered-source` 返回不支持，不能把修改后的文件当作修改前快照。

首次写入前仍需 Agent 完成真实基线采集。服务保留版本检查、去重、检查点、写后读回、真实编译、保存关闭重开及必要复编；基线顺序是 Agent 工作流程，不新增服务端强制事务。

服务派发前检查磁盘哈希、路径和占用标记；原生桥接在打开前再次检查版本及排他读取，打开后再核对磁盘版本。它只处理自身创建的 IDE 句柄，不关闭外部工程。排他探测与 IDE 打开是两个步骤，不宣称整个操作是操作系统级原子事务或支持外部并发编辑。

直接修改、创建以及显式保存前保留内部检查点。不确定修改不会自动回滚、恢复或重复写入；保留原始异常和现场，按原操作查询。检查点不是另一份交付工程，也没有自动恢复承诺。

新直接打开不调用工程复制 PowerShell 助手。旧副本创建和维护仍可能调用已有脚本，脚本信任问题未因此解决。
