## 实际实现与接口

| 接口 | resident行为 |
| --- | --- |
| `project_open(sessionMode="resident")` | 直接打开指定文件并保留原工程句柄；不复制业务工程 |
| `object_list` | 根级普通ST POU目录；返回residentVersion和excluded；续页须expectedResidentVersion |
| `object_read` | 原生GUID、所属Application、路径、ST标识、声明及实现原文、contentHash和residentVersion |

只增加三个可选输入字段，不删除旧输入或改变38项输出Schema。38项工具不等于38项均支持resident。普通用户仍只说路径、目标和需求，内部身份及版本由Agent读取。

## 用户操作与停止规则

- 手动修改源码：旧版本请求在零派发时拒绝；后续新指令可先读新内存再决定。不会悄悄刷新版本并执行旧请求。
- 手动保存或外部磁盘变化：当前无法独立区分来源，因此任何跨请求主文件哈希变化均停止本会话；同字节换文件身份也拒绝。尚不支持安全继续手动保存后的会话。
- 手动关闭／换句柄、PID复用、超时、异常退出或写后缺证：停止，不重开、不重放、不回滚、不恢复性保存。首次异常与取证异常分别保留。
- 明确零派发的选择/版本拒绝不会永久毒化接收器；发布证据失败或归属无法确认则保守停止。
- 相同requestId沿用原操作。resident操作的reconcile只观察原记录，不套用旧结果文件加进程退出重新判成功。
- EOF停止新受理，等待在办请求并保留进程观察；不授权保存或关闭。IDE仍活时服务与原租约保留。首版不提供重新接入或自动释放常驻会话；即使后续退出，也不能把未保存内容判为已保存。
