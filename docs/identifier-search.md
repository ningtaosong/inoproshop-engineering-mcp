# 完整标识符源码检索（0.14.0候选）

在原project_search中增加matchMode，不新增工具，共二十项。当前候选分支codex/identifier-search；main仍为0.13.0。本页描述源码出现位置，不是编译器符号表、语义交叉引用、读写或安全重命名分析。不会改变量、工程、设备或任务。

## 两种模式与默认值

| 方式 | 范围与含义 |
| --- | --- |
| literal（默认） | 保留原字面子串行为；areas默认name/declaration/implementation，包含注释和字符串，中文及标点按原文字面检索。 |
| identifier | 单个完整标识符形态词元；须显式areas为declaration/implementation的非空子集。不允许name或包含name的默认全部区域，不静默缩小范围。跳过注释、字符串和已识别的数值/类型化字面量。 |
| variable_inspect | 另一个既有只读工具，限定语法的变量声明解析，返回声明区、类型和显式初始化等，不是出现位置检索。 |

两种搜索都保持caseSensitive（默认false）、limit（1..100，默认50）、maxResults（1..1000，默认200）及精确工程/Application身份。用户只给路径和业务名称，Agent查询身份。identifier查询只能是一个名称，例如Config2；GVL_AlarmConfig.Config2.DelayTime必须拆成名称查询，不能作为一个identifier参数。成员链中的Config2可以命中，但没有因此确定变量实例、类型成员或符号归属；同名局部和不同对象逐项保留。

标识符形态采用Unicode字母或下划线起始，后续Unicode字母/数字/下划线；组合附加符等不在本版词法范围。按完整词元匹配，Config、Config2、MyConfig、Config_Extra不互作子串。大小写比较不改原文字段或位置。关键字和类型名称的同形文字不进行语义分类，不当作已识别的用户变量。

## 词法与位置

复用声明查询的顺序词法基础，声明解析的默认行为/版本保持v2；新搜索使用严格标识符模式st-identifier-v1。支持//、平衡嵌套(* *)注释、单/双引号字符串、$转义及双写引号。不先删字符串/注释，不把Con(*注释*)fig拼成Config，位置始终指向原文。

能划定普通十进制/指数/基数字面量及常用基础类型、BOOL、TIME和日期/字符串类型化字面量边界；不进行值求解或ST语法编译。不支持字符、未知类型化字面量或未闭合/多余注释终止等产生可定位缺口，停止该源码区域余下的推测，保留此前已确认词元。相邻未知字符可能继续前一个词元时也不将该词元作为完整匹配返回。其他对象/区域继续读取，不能将部分扫描写成完整。

matches保留实际对象GUID、路径/类型、contentHash、region、matchedText和适量context。正文规范为LF，与object_read相同；UTF-16偏移从0起、结束不含，行列从1起。名称命中仅literal可用，position为null，不能伪造代码行号。未闭合区域的gap位置覆盖不可信余段，context只是原文片段，必要时object_read读取对象全文。

## 覆盖、分页与版本

scope继续说明枚举、读取失败和跳过对象；identifier另有lexicalCoverage，分开记录扫描区域数、完整区域数及gaps。读取完整不等于词法完整；maxResults导致的page.truncated也与词法缺口分开。无命中且任一相关读取或词法缺口存在，不得断言整个工程不存在该名称；有缺口时totalMatches为null，保留已确认命中数。

searchVersion=source-search-v2、matchMode及identifier词法版本纳入内容版本摘要，与工程/Application、磁盘、内容、查询/区域/大小写/上限及实际覆盖共同绑定。按返回nextOffset和expectedVersion取页，limit可改变，但不能改语义条件或跨工程。首查一次受管理IDE读取，续页从原observed-after-exit证据重新核对，不重新打开IDE；readOrigin与pageFileEvidence分别说明原采集和本次文件核对。没有持久索引或新工程读取通道。

合法0.13.0字面清单经原证据核实后明确返回SEARCH_SCANNER_VERSION_CHANGED冲突，要求显式重新首查，不冻结、不悄悄重解释旧页。缺失/损坏证据、原发布结果与原文不符或无法确认的版本仍unknown冻结；不是普通升级。查询/文件变化正常冲突，不混页。已有隔离及原操作查询规则保持，unknown不重放、不删锁、不换目录。

## 使用与结论边界

例如：“沿用正常双路工作副本，只读用完整标识符模式查Config和Config2，明确声明/实现范围，取完小页并读取命中原文后说明位置；不修改、编译、保存或连接PLC。”Agent须实际传matchMode=identifier及合法areas，再用object_read解释。

词元命中不能证明完整引用关系、变量未使用、没有其他写入，或删除/重命名安全。未命中也受实际支持源码、覆盖/词法缺口和截断影响；没有设备/I/O、库或在线运行语义。只读任务不建立修改基线，不编译或保存。历史CmpLog、脚本信任、原unknown/隔离、11/12回答质量及展示限制保持，不把旧诊断记作本轮新编译。

实际构建/自动化、真实MCP和DSH CLI结果分开归档；独立初始化不证明DSH收到Schema/指令，CLI也不等于桌面交互、链接点击或运行验证。参见[工具Schema](tool-schemas.json)、[入门](getting-started.md)和[工作指令](../instructions/inoproshop-workflow.md)。
