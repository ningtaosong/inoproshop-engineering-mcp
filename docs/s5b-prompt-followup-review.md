## 补修代码复核

`WindowsDialogBackend.remains` 在确认之后仅查询原 HWND 的 Win32 `IsWindow` 和 `GetWindowThreadProcessId`，不再调用 `dialogs()` 或重新枚举 UI Automation。原窗口已消失返回 `False`；仍属当前 IDE 进程返回 `True`，桥接保守判不确定；句柄归属改变、进程查询失败或抛错均保守判不确定。初始精确提示识别仍使用 UI Automation，并绑定当前服务启动的 IDE 进程创建身份、模态窗口、全文和按钮结构。独立 PowerShell 加载本机 ScriptEngine 3.5.11.10 的 IronPython 程序集，证明两个 Win32 接口可调用；它没有验证真实 IDE 内的线程交错。

原生打开返回或抛错后，主线程将观察器标记为停止，最多等待原有 1000 毫秒；如果初始 UI Automation 查询或确认后查询仍未结束，则保留句柄供 `final-cleanup` 处理并返回不确定，不提高等待上限、不忽略活线程。迟到的初始查询结果不再产生新的“已观察”记录或点击。确认失败且曾观察到目标提示时，即使原生打开恰好返回，也不能把提示处理记为成功。无提示、确认成功及原生打开异常的结束路径分别由生产包装函数替身测试覆盖。

每个已列入的打开阶段最多处理一次，`initial-open` 结束并确认观察线程退出后才可进入 `reopen`；同一阶段再次启动或前一观察线程未确认结束时拒绝。保存后重开与初次打开共享截止时间，最多两次阶段确认，不创建并行观察线程。提示记录只证明观察与确认动作，正式成功仍需原生调用、关闭、结果发布和最终文件证据。
