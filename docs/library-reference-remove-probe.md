# S5：精确移除直接库引用可行性探测（2026-11-18）

**决定：② 目前只适合做只读移除评估。** 本次确认了本机原生接口和两份一次性 AM610 夹具的写前判断，没有执行移除、卸载或移除后复编。不能把脚本接口存在、源码无命中或加入库后的编译通过当作安全删除的证明。

## 对象和实际接口

基线 main 为 `b0f3fb799e4293c161273b064d09a48cf0817148`（0.28.0、31 项工具）。本机 InoProShop 为 1.9.1.6、ScriptEngine.plugin 3.5.11.10、IronPython 2.7.7。复用了产品 `library_inspect`、`library_reference_add` 使用的原生直接引用读回、安装目录身份计算、配置版本及离线编译函数，未进入 MCP 派发，也未改变这些函数。

- 精确限定到原生 Application / 库管理器（管理器类型 `adb5cb65-8e1d-4a00-b70a-375ea27582f3`，实际父对象为该 Application）。每份夹具均只有一个目标：原生引用 ID、管理器 ID、命名空间 `MATH`、固定库对象与安装目录身份一致。库为 CAA Mathematics 3.5.11.0，厂商 CAA Technical Workgroup；版本和厂商来自原生字段，不是解析显示名。加入后保存重开确认目标原生 ID 不变、另 18 条引用逐项一致。
- 实际对象上看到 `IScriptLibManObject.remove_library(name: str)`，没有验证按原生 ID 删除的接口，也没调用按名称删除。未来即使有确切未使用证据，仍须把写前选中的原生对象和该方法的选择器一对一绑定；同名、归属或语义有歧义就停止。此对象的 `is_managed=true` 仅表示固定安装库引用，不是“由设备管理”；归属由精确父管理器、非占位符/非系统标志以及本次有据可查的原生加入共同确认。任意现有工程不能靠单一标志推断用户归属。
- 本机仓库另外暴露 `ILibManager.uninstall_library(repository, library)`；该接口改变本机安装，不是工程操作，本轮未调用。也未触碰占位符、清除显式覆盖、设备/系统管理的引用或传递依赖。
- 本机暴露 `ScriptLibraryReference.get_dependencies()` 与 `ManagedLib.dependencies`。读取了能确认的固定安装库声明的依赖字符串：目标列表为空，其余 18 条不属于此次固定安装对象的元数据覆盖；不能由此排除反向或传递依赖。CODESYS 官方脚本手册指出依赖遍历遇环有风险；本轮未调用递归展开，只记录脚本成员及固定库声明。[脚本库管理参考](https://content.helpme-codesys.com/en/ScriptingEngine/ScriptLibManObject.html)
- 在实际管理器、引用、Application、工程及 `PLC_PRG` 可见的脚本成员中，未核实到能够返回完整、编译器解析后的符号使用关系及其覆盖范围的接口。厂商 IDE 存在符号交叉引用并不表示本机脚本接口暴露同等覆盖。[交叉引用视图](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_cmd_view_cross_reference_list.html) 普通直接引用、未限定名称、编译库内容、原生非文本或不受支持的对象、设备/系统配置和传递依赖都不能靠当前 ST 文本查询排除。文本读到的是候选位置，不是绑定到库的语义证明；`qualified_only=true` 是这两个夹具的原生字段，本轮未实测未限定调用，也不把该标志推广到其他库或其他工程。

## 复现及下一步

两份夹具的原始证据归档于 `InoPro-review-20261118-125658.zip`，SHA-256 为 `268445b2422b1faf2625052c436abe42f7fb29094400fc76b9ff98793d740b18`。其中保留了实际执行的两个脚本。公开启动器将原本固定的本机路径改为显式参数；收尾仅核对归档、代码和链接，未重跑探测。脚本仅用于独立验收夹具，由维护者手动启动。日常启动、MCP 工具注册和产品调用均不引用它。

仅在另行授权复测时，在独立 Windows 目录 `D:\InoPro-LibraryRemove-Probe-<时间戳>` 用与归档相同的只读种子哈希准备两个新夹具 `unused/AM610_unused.project`、`used/AM610_used.project`。确认无其他 DSH/IDE 占用后手动运行：

```text
node scripts/probes/library-reference-remove-launch.mjs "<新夹具目录>" "<InoProShop.exe 的绝对路径>" "<实际日常登记目录>" "<已核对固定构建的 dist/lease-process.js 绝对路径>"
```

启动器只读检查指定的日常登记、租约和历史 unknown，不接管或修改它们。复测需重新确认样例版本、安装身份及独占条件，已有探测目录不再使用。

只读报告区分明确在用、在实际检查范围内未见使用和覆盖不足。可直接使用[只读检查示例](getting-started.md#只读检查库的使用情况)。

重新考虑写工具须同时满足两项前提。

1. 写入前能将原生移除接口的选择条件与选中的直接引用唯一绑定。需核实同名、不同版本和不同管理器等情形。
2. 能说明使用关系及反向依赖的实际覆盖，包括未限定名称、非文本对象和编译库带来的缺口。覆盖不足时停止。

`remove_library(name)` 存在、目标库声明的依赖为空、保留引用时的编译成功，均不足以满足这两项前提。清除占位符显式覆盖仍是单独的未实现项。
