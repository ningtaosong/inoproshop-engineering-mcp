## 最小保护变化

1. 工程派发前，在实际主线程确认 UI、无打开工程、精确公开命令与可调用方法；校验固定 worker／helper 指纹。`noUI` 在启动前明确拒绝。没有此能力不派发工程命令。
2. 既有业务、工程清理、检查点和 unknown 规则保持。结果发布后再次核对空工程，再用直接 Python callable 排队一次公开 FileExit，参数为原生空 string 数组。回调中再次确认空工程与命令身份，不强制退出、不自动保存、不尝试其他入口。
3. 分别保留 preflight、queue、queued、callback、dispatch、returned 或 failed 回执。绑定 operationId、requestId、launchId、请求指纹、请求文件哈希、PID 和进程创建身份。原业务结果文件保持原文；首个关闭错误独立保存，记录器错误另外保留。
4. 父服务的可信 process-exit 回执再绑定关闭文件及 stderr 哈希。新请求必须同时满足原进程正常退出、完整同源关闭记录、没有失败记录或日志错误。关闭失败后人工退出码 0、记录丢失／损坏／归属不符、退出后补写回执均不能变成成功。服务重启继续执行相同规则。
5. 公开命令返回但不退出：原有有界业务超时生效，保留观察，不 kill 或重新派发。迟到退出只留证，未隔离操作仍按原正式核对规则处理，不自动升级终态。

旧请求没有 `normalClosePolicy` 时，保留其原退出证据规则，不批量修改历史记录或补造回执。正式隔离只观察、终态幂等和可信退出保护没有放宽。新回执只进入内部 IPC／unknown 诊断数据，38 项 MCP 输入输出 Schema 均不变。初始化说明仅更新版本文字，含客户端标题实测 64,431／65,536 字节。

本次仅共享产品 `bridge/worker.py` 采用新退出方法。旧独立探测辅助脚本仍可能含 `system.exit()`，没有宣称所有脚本均已补修。
