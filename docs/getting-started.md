## 接入 DSH

1. 备份DSH配置。实测桌面配置入口为 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`，以所用DSH版本为准。
2. 参考 [配置模板](../config/dsh.example.patch.yml)，将条目加入已有顶层补丁数组。更改Node、仓库、IDE和Profile路径；保留客户端config层的 `maxInstructionBytes: 65536`，与serverName、transport同级，不放进env。不覆盖模型凭据或其他插件条目，不重复添加同名MCP。
3. 新安装可使用模板的独立数据目录；已有部署升级沿用原目录，保留登记、操作、检查点和隔离，不通过换目录或复制故障工程绕过unknown。
4. 空闲且没有活动任务/用户输入时正常重载MCP或重启DSH。新工具/Schema需要重载，普通新对话与工程切换不需要反复重载。
5. 新对话先让Agent查询环境、会话和工具集合。加载当前候选应为0.20.0、二十五工具，实际收到property_create的PUBLIC/DINT、父FB与Get源码参数，以及code_apply_change的property_get、FB/Property身份及结构/内容/磁盘版本参数；原method_create及任务编辑参数保留，以及project_create的新路径参数及project_open的projectPath参数、project_compare的current-project来源及当前指令；variable_inspect保留includeInitializerMembers及maxInitializerMembers。显式提取后的memberExtraction.parserVersion为named-initializer-members-v1；未启用时仍declaration-variables-v2。project_search的matchMode=literal/identifier及st-identifier-v2不变，identifier必须显式指定不含name的源码areas。若仍为旧Schema，停止需要新能力的任务，待空闲正常加载。初始化返回instructions不单独证明客户端收到或模型正确遵循，独立CLI不推定为桌面同会话或界面交互通过。

DSH通过stdio启动Node。不要在同一数据目录被DSH占用时另行运行 `npm start` 或第二个客户端；命令行直接启动MCP只会等待协议输入。

启动失败先区分解释器/路径、策略/信任、模型/网络及租约占用。可运行不启动工程服务的[本地诊断与正常移交步骤](startup-handoff.md)；不要固化临时Bypass或递归解锁。检测到用户输入时停止自动退出，原服务未确认退出前不启动另一客户端。脚本诊断及随后一次正常服务移交已分别取得证据；前一次因输入活动停止的记录保留。这只证明该次移交与三个状态查询，不证明历史信任/崩溃根因消除或所有启动场景可靠。

### 指令大小与连接失败

`maxInstructionBytes` 属于 **DSH MCP Client** 的配置，不是本MCP服务参数或INOPRO环境变量。2026-11-02接入核对时，本机DSH和 `@deepseek-ai/dsh-mcp-client` 均为0.2.0-rc.2，客户端Schema支持此正整数；默认32768字节。该客户端将服务器instructions去掉末尾空白，添加 `### MCP server: inoproshop` 标题及两个换行，再按UTF-8字节计量；超限拒绝连接，不是工具执行超时，也不是静默截断。

2026-11-02本机实际指令文件35593字节，客户端计入标题后35619字节，超过默认上限。实际桌面配置提高到65536并正常重载后恢复十八工具，真实DSH任务完成了修改前基线、修改、保存版复编和最终比较。模板已同步这一设置；不通过缩短或截断已验工作规则掩盖问题。其他客户端版本以各自Schema为准，不能假定都支持同一字段。

修改指令或接入前可运行：

```powershell
npm run check:instructions
```

该静态检查按实际UTF-8字节核对模板的明确上限，同时检查客户端归属标题的开销；超限、字段缺失/错层或配置格式不明确时非零退出，不改文件、不启动服务/IDE。检查器只解析仓库内简单单客户端模板，不是通用YAML校验器或私人配置审计工具。未来指令增长仍需检查，不保证65536永久足够；超限时先停止接入并复核，不能静默截断。

初始化单独成功只证明服务提供指令和工具，不证明DSH客户端已接纳或模型遵循；桌面断连错误、已安装客户端Schema/实现、修复后实际系统指令及工程调用是本次接入复核的不同证据。不要因为独立握手成功就反复重启IDE或派发工程操作。已有正常DSH无需因阅读本说明再次重载。

## 工程与副本

默认指定哪个 `.project` 就操作哪个文件。Agent 用 `project_open` 打开该绝对路径，完成读取、修改、编译、保存重开；交付链接仍指向该文件，不自动创建业务副本。工程须已保存、可读取且没有外部 IDE 占用；不能接管未保存内容。已有外部版本冲突会停止，不通过重新打开或换目录绕过。

旧 `project_open_copy` 只在明确需要独立副本时使用，仍不覆盖来源。直接指定旧副本路径会复用那个文件的身份；直接指定原来源路径不会跳转到旧副本。现有副本、来源、旧记录和隔离工程保留，不批量迁移。

内部检查点用于故障追溯，不是用户需要管理的交付副本，不会自动回滚指定工程。默认不采集比较快照；只有明确要求本轮前后比较时，才在首次写入前采集 current-project 基线。直接编辑没有不变的 registered-source。详细语义见[直接编辑说明](direct-project-edit.md)。

第一次直接打开会将登记容器升级为 v2，旧条目和文件不搬迁。切换 DSH/Codex 前，双方服务入口都须使用 0.16.0 或更高兼容版本；本指南引用的固定 0.14.0/0.15.0 入口属于历史验收配置，不能接管已升级的目录。不要降级登记格式或换空目录绕过。

## 日常修改闭环

S1 已合入main，为 0.18.0／二十三工具，新增 [已有周期任务配置编辑](task-config.md)。0.17.0及下列固定客户端历史记录保留原归属；使用新工具须正常加载对应固定构建，不能把代码更新当作客户端已收到。已有任务仅可改整数毫秒周期及优先级，先读取任务配置版本和磁盘版本；任务变化后须真实新编译，ST全文不变也不能沿用旧编译。其他任务字段只核对实际可读项，不宣称完整设备配置一致。

指定工程和修改需求 → 必要读取定位 → 直接修改指定文件 → 真实编译 → 保存、关闭重开 → 根据保存结果判断必要复编 → 修改对象最终读回 → 简短报告。

用户在客户端指定 `.project` 文件，或提供其完整路径，再说明要改什么即可。已有文件上下文能唯一定位时不用重复填写路径；内部工程身份、哈希和工具参数由 Agent 处理。普通任务不追加全工程源码检查、修改前基线或最终工程比较。

Agent 内部仍核对环境、会话、登记，读取目标对象完整原文、当前哈希和判断影响所需的接口。变量或成员查询按定位需要使用；使用成员提取时启用 includeInitializerMembers=true，核对父名、成员名、显式值和原文位置。预览、旧位置、多结果、原值不符、归属不明或相关缺口时停止，不补造初始化、不全局替换相同数字。类型字段初值、GVL 聚合初值和块输入初值分别保留。

原版本和磁盘变化校验、检查点、去重、冲突检测、写后读回及保存重开继续保留。工具内部的全工程文本 snapshot 是版本和保存检查的一部分，与 project_compare 基线不同；取消默认比较不省略 expectedHash/expectedSnapshot。保存改变磁盘版本时按结果复编，编译证据须适用于最终文件。最终核对修改对象；如再查变量/成员，使用新内容版本，不复用修改前位置。

只有用户明确要求比较时，才按[按需比较说明](post-change-baseline-compare.md)在首写前采集 current-project 基线，完成修改闭环后采最终快照并取完比较页。要求的比较无法完成时在写入前说明并停止；修改后才提出比较而无可信历史基线时，如实说明缺失，不补造或重放写入。未要求比较时，缺少比较工具/基线不阻止普通修改，也不是必须补验的待办。

默认简述实际改动、编译错误/警告及必要影响、保存重开和目标读回，提供工程链接与独立完整路径。仅实际做了比较才报告差异结果；不能把未检查的其他对象、任务、设备/I/O说成已核对一致。出现意外变化、冲突或 unknown 仍停止并保留现场，不自动回滚。这是 [Agent 工作指令](../instructions/inoproshop-workflow.md)调整，没有新增服务端事务、变量写入工具或自动回滚保证。

此流程需要客户端实际加载更新后的工作指令。固定服务入口不会随其他工作区的文档修改自动更新；在后续正常、空闲的加载时使用更新指令，不强制结束客户端或丢弃输入。既有 MCP/DSH/Codex 的完整比较验收仍归属原任务，不能当作本次简化流程已通过模型验收。

## 创建 ST POU

pou_create仍是一项工具，限定精确Application直接根节点，三类均提供requestId、projectId、applicationId、parentId=applicationId、当前expectedSnapshot、name、完整declaration及implementation。用户只提业务需求，内部身份由Agent查询。 expectedSnapshot取最近打开/创建/修改/编译返回的工程文本snapshot，不取project_compare的内容版本snapshot.version；每次创建后使用新返回的工程值。

| pouType | 声明首部与返回参数 | 范围 |
| --- | --- | --- |
| function_block | FUNCTION_BLOCK 同名对象；不传returnType | 保留原调用兼容性 |
| program | PROGRAM 同名对象；不传returnType | 声明和实现；不会自动加入周期任务 |
| function | FUNCTION 同名对象 : 对应类型，类型后换行；必须显式returnType | 只允许DINT、BOOL、INT、REAL、TIME；缺失或未列类型拒绝，不自动选择或退化为DINT |

创建参数returnType沿用大写枚举，声明名称及返回类型按既有规则不区分大小写核对。客户端JSON Schema中的returnType为可选枚举；FUNCTION必填及其他两类禁用由工具说明和服务端条件校验约束，不能仅从required数组推断FUNCTION可以省略。STRING、数组、结构体、指针、引用、自定义别名和其他数值类型不在创建范围；此限制不收窄已有对象的读取、检索和比较，不改写其返回声明。

object_list/object_read保留原objectType分类：功能块为function_block，PROGRAM/FUNCTION为st_pou，由可选pouType细分。returnType来自实际声明首部；本机原生对象没有已核实的独立pou_type/return_type getter，pouTypeSource明确采用原生POU类型身份和声明首部，不伪装独立属性采集。完整原文、版本、创建工厂枚举和真实编译用于核对。
