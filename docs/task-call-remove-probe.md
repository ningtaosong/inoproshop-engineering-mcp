## 结论与四项验收

**当前不足以开发限定移除工具。** 本机可以读取完整有序调用行，发现了按名称和按整数索引移除的接口；但唯一一次实际 `remove(1)` 抛出 `System.ArgumentException`：

> 未在指定的集合中找到指定的项，因此无法移除该项。

原生栈位于 `System.Collections.CollectionBase.System.Collections.IList.Remove(Object value)` 和 `ScriptCommonBaseGeneric.PerformWithWriteableCopy`。这解释了本次停止位置，尚不能仅据此确定底层集合实现的根因。

| 验收项 | 本次结果 |
| --- | --- |
| 原生定位 | 已确认零基索引、完整名称/注释、目标唯一 PROGRAM 身份，以及同句柄写前复核；目标索引为 1 |
| 移除 | 只派发一次 `remove(1)`，发生上述异常；结果保持 `unknown`，没有成功的写后调用列表 |
| 独立 IDE 重开 | 未执行；首次原生结果不确定，启动器未进入第二进程 |
| 移除后的保存版编译 | 未执行。只有移除前已保存基线的编译：0 错误、0 警告 |

不重试名称重载，不清空重建调用列表，不删除 PROGRAM，不自动回滚或恢复性保存。工程配置中的调用顺序与实际任务调度是不同证据，本次没有运行观测。

实际环境：InoProShop 1.9.1.6、AM610 设备描述 `4102 / 10f4 0002 / 3.5.11.11`。本次原始快照中的 `device` 为设备身份的权威记录。

`3f2472c176f082477ecd8c940d0daffe2436a62ebfafc84d8812661ef605a143`。

原生集合类型为 `ScriptPouObjectList`，绑定方法帮助实际返回：

```text
remove(self: IScriptPouObjectCollection, pou_name: str)
remove(self: IScriptPouObjectCollection, index: int)
```

本机方法元数据 `0x060001d2` 是名称重载，`0x060001d3` 是整数重载。读取 `pous[0]` 得到 `PLC_PRG` 和空注释，整数重载使用索引读取入口。名称重载有首次名称匹配风险，本次未调用。官方[调用集合说明](https://content.helpme-codesys.com/en/ScriptingEngine/ScriptTaskConfigObject.html)仅作辅助，结论以本机安装件、绑定帮助和本次实际调用为准。

选择绑定完整有序原生二字段记录、索引、任务 GUID、Application GUID、当前任务版本、PROGRAM GUID/原生 ST 标识和磁盘哈希。实际索引不是固定产品槽位；本次计划明确选择三条记录中的第二项。缺失、同名重复、位置变化或字段不完整时不能改选其他项。

## 首次夹具准备失败（保留原记录）

较早的独立目录 `D:\InoPro-S8a-TaskRemove-20261119-152525286` 在 `read-baseline` 后报告 `Baseline fixture differs`，移除派发次数为 0；未保存新基线，主文件仍为种子哈希。该次没有单独持久化造成不等的完整基线，因此不能补造第一份原始差异。

检查安装件后发现 `add(name, comment)` 的该版本实现未读取 comment 参数。最终夹具准备按已核实的索引，用 `replace(index, sameName, comment)` 单独建立区分度注释，并分别持久化新增前后记录。**这一动作仅发生在保存基线之前的夹具准备阶段**；正式移除阶段没有调用 replace、clear 或重新添加来模拟删除。第一次的脚本指纹保留于 intent，但未另存当时完整脚本。复核包的 `executed-scripts` 保留第二次实际执行版本，与 intent 哈希相符；入 Git 前仅移除文件末尾多余空行，Python AST 不变，指纹差异单列。

第一测试实例曾对精确匹配的自有进程调用正常窗口关闭请求，随后仅观察到进程退出；无可核实退出码，原失败结果未改写。旧夹具、原生标记及失败日志保留，没有重新打开。第二份夹具是在确认第一份没有移除派发后重新从中性种子准备；两份合计只有一次实际移除调用。
