# 0.34.3：追加／替换的任务集合枚举核对

本分支基于 main `fd43f679707e0f484611b7f03174fa864add316a`，仅修复 `task_call_append`、`task_call_replace` 的任务集合比较及失败取证。版本为 **0.34.3 修复候选版、37 项工具**。未合并、未部署；未启动真实 IDE、工程 MCP 服务或 DSH 模型任务。

## 已确认的问题与复现边界

确定性替身调用生产 `bridge/worker.py`：只调整顶层任务返回顺序，原任务身份、配置、源码和内部调用均不变。原版本 8 个桥接场景中，5 个失败：追加的即时／重开读回，以及替换的派发前／即时／重开比较。追加原来没有相同的派发前完整集合复查，因此该场景原来通过，并不证明原路径已充分检查。

服务端通过实际 EngineeringService 和 FixtureAdapter 提交追加／替换结果，仅改变 `afterAppend`、`afterReplace` 或 `after` 的顶层任务顺序。原版本 6 个场景中，4 个换序场景误判 unknown，两个不换序场景通过。

这些是生产比较路径的离线缺陷复现，不证明旧真实故障的唯一原因。最初 Node 替换测试误传额外参数，首次 Schema 拒绝记录保留；修正测试输入后记录上述 6 场景。测试编写过程中关于冻结拒绝返回形式／文案的断言错误也保留，未修改服务既有停止语义迁就断言。

## 最小行为改变

任务集合枚举顺序不作为配置差异，任务内部调用顺序仍严格核对。

- 比较时仅将顶层 `tasks` 按唯一原生 `taskId` 建立独立视图。重复、缺失、非 GUID、零 GUID 和大小写变体重复身份均拒绝。采集快照不排序、不覆盖。
- 派发前、即时读回和保存重开分别核对完整集合及所有字段。任务内调用的位置、名称、中文／空／字面文本 `None` 备注、PROGRAM 身份、ST 标识、源码、路径、看门狗、覆盖和读取失败继续严格检查。其他数组仍有序；未知字段不删除，null、空文本和字符串不合并。
- 追加补齐同句柄派发前完整集合／PROGRAM／源码／磁盘／检查点复查；替换原有复查使用相同身份视图。真实变化在派发前停止，原生 add／replace 和保存均为 0。
- 桥接在上下文校验前保存实际观察的清单，核对文件保留具体差异、首次异常及独立的日志／partial 读取异常。写后失败保持 unknown，不回滚、不恢复性保存。
- 服务端对即时和重开结果独立核对，并为每次验证保存单独目录，重启 reconcile 不覆盖前次证据。证据发布失败也不能接受成功；首次校验异常优先保留。
- 复用 task_create 的内部比较帮助函数，但未改变 task_create 路径。task-configuration-v1 算法、输入输出 Schema、初始化指令及其他工具范围不变。
- 0.34.2 的正式隔离仅观察、终态幂等和请求／进程退出证据保护原样保留。

这不提供任务调用重排能力，也不改变 PLC 调度语义。单条移除缺陷、重排原生入口缺口继续保留。

## 验证与下一次最小真实复验

离线运行原生桥接替身和服务层结果校验，覆盖顶层换序、内部顺序、增删、备注、类型、身份、源码、ST、覆盖、日志失败、请求去重、冻结和重启核对。完整测试结果及提交归属在验收归档段独立记录，不把定向和完整计数相加。

本轮不触碰历史 unknown、隔离、账本、锁、租约、封存工程或日常配置；不恢复历史字节。默认环境 200 ms 性能失败、IDE 崩溃根因、CmpLog、脚本信任、Desktop 欢迎页及运行验证限制未解决。

复核补修后，再独立授权真实复验。建议追加、替换各使用一份全新且非隔离的 AM610 夹具，至少含两个普通周期任务及可区分备注；核对固定构建、原登记与排他条件。各只派发一次，记录派发前、即时和重开原始清单，核对旧任务配置、内部调用顺序、PROGRAM／ST／源码、真实退出证据及保存版编译对应文件。未实际换序时只报告该次正向闭环，不宣称真实 IDE 复现换序。出现 conflict／unknown 即停，不回滚、不重放，不以新目录绕过冻结。模型复验另行安排，不作为本轮离线通过结论。
