# 常驻修改后保存与连续操作（0.42 候选）

用户于本轮将流程改为“每完成一次修改就自动保存”。本分支对应 agent.md 路线第6项，替代未交付的手动接纳版本方案；原 `10febc56` 提交、包和原时点记录保留。当前候选恢复38项工具，不注册 `project_accept_saved_version`。日常DSH仍为0.38.0，Codex及当前真实停止实例未改变。

## 当前合同

首版仍只限同一 MCP 服务、自有 IDE、指定工程中已支持的 Application 根普通 ST POU 实现区。`code_apply_change` 使用现有对象身份、原文哈希和 residentVersion；不改声明，不增加其他对象类型或声明编辑能力。原38项工具的验证结构和输出Schema保持；`project_open.sessionMode` 的描述注解同步为自动保存语义，不改类型、默认值或必填规则。

一次实际修改的流程：

1. 重读当前内存、磁盘和租约，发布检查点；二次读回确认后替换实现区一次。
2. 严格核对授权后的源码和全部既有受检依赖。原生发布保存就绪证据，Node按同一请求独立复核，并核对原文件身份、内容、时间和锁未改变，然后在原IPC发布一次保存许可。
3. 原生再核对同句柄、路径、内存、磁盘及租约，公开调用该工程的 `save()` 一次。没有额外工具、用户二次确认或私有编辑器调用。
4. 保存正常返回后，要求两次公开读回一致、dirty均为严格false、源码及受检结构保持、磁盘版本已变化且稳定；Node再次独立验证、绑定新文件身份及提交登记，才报告 saved=true。
5. 保持工程与IDE打开。下一次读取使用新版本；同一requestId返回原操作，不重复修改或保存。正常关闭后再显式打开，逐请求验证原intent至当前文件的本服务保存版本链，旧记录不改写。

保存提交**当前工程全部未保存内容**，不仅是本次目标对象。用户已有的其他未保存内容会作为写前状态保留，并随工程一起保存。没有变化的请求、只读请求和单独编译均不保存；相同文本请求为no-op，不创建新的修改或保存派发。编译仍按明确任务要求执行，只报告绑定的当前内存编译结果；自动保存不等于已经独立重开或验证PLC行为。

## 证据及停止条件

公开 `ScriptProject.save` 是零参数、void返回。已归档的本机安装件显示其调用底层Save，并在适用时设置ExplicitlySaved。此前发现ProjectSaved事件早于最终文件提交，所以本实现不订阅Core事件、不靠事件或dirty单项宣称保存成功。复用证据来源及安装件SHA在复核包 `public-save-evidence.json`；这不是本轮真实保存验收。

原始 before、checkpoint、predispatch、after、verification 及保存前后读回分别保留。`save-ready`、`save-authorization`、`save-call`、`save-returned`、`save-receipt`、`saved-channel-accepted` 和登记回执均绑定原请求。sourceHash、原intent、旧请求/结果不随保存被改写。

保存返回但文件仍旧、dirty未清、读回变化、磁盘不稳定、结果或登记发布失败，均不得报告成功。已修改或已尝试保存后出现异常时为unknown并冻结后续写入，保留首错和取证错误，不重存、不反向替换、不恢复性保存、不关闭。外部保存或文件替换没有本服务保存回执，不能静默接纳。保存前门只证明其观察时点；公开save没有文件CAS接口，不宣称排除了最后复核与调用之间任意外部并发写入。

旧生产请求中“修改但不保存”的完成记录保留其历史验证语义；当前新修改必须具有自动保存协议和完整回执。正常重开兼容只接受全部请求已明确完成、原IDE有正常退出回执、原服务创建实例已退出、保存链完整且当前文件匹配的情况，不恢复stopped/unknown，不接管仍存活的实例。
