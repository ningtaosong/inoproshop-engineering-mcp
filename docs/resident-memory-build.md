## 实际实现

resident 的 `project_build` 新增可选输入 `expectedResidentVersion`：在resident执行时必须来自当前读取，服务队列和实际IDE句柄再次核对。旧batch输入与执行不变；该字段不能用于batch。其他37项输入与全部38项输出Schema保持，新增结果字段使用已有passthrough契约。内部身份仍由Agent读取，用户无需填写GUID或版本。

调用现有公开 `Application.build()`，不打开新句柄、不保存、不关闭重开、不退出。原生消息先清除，编译后重新枚举消息分类和全部消息；调用返回、分类完成、条目数、严重程度、原文及可读定位字段均留证。完整诊断中的error表示请求完成但 `buildPassed=false`，保留源码、允许后续明确授权修正；调用异常、超时、缺证、进程变化及无法解释的保全差异仍冻结，不重放或恢复性保存。

编译前保留完整内存检查点、原磁盘哈希及同句柄复查。清消息和证据发布后，紧邻原生build再次检查请求期限、停止标记、租约指纹和磁盘。`buildInputResidentVersion`绑定编译前依赖；`builtSourceVersion`绑定实际Application、工程句柄及全部已读源码/身份。Node独立重算，不能只信编译后snapshot或result.json的succeeded。`buildEvidenceScope=resident-memory`不表示磁盘文件已编译。登记的lastBuild仅适用于同launch、同内存版本、同磁盘及Application；下一次改源码即失效。

请求完成证明按原请求command检查计数：build必须恰一次，其他已迁移请求仍为0；保存、重开、关闭及退出均为0。已正常关闭的旧会话证明沿用原生产者记录，不把新编译规则套到旧非编译操作。

## 编译变化边界

原始快照不删除、不排序：已有节点、源码、ST标识、任务字段、看门狗、任务内调用名称/备注/顺序及直接库引用/解析字段逐项保持。仅公开归类为 `library=true, primary=false` 的后台库工程可加载或卸载；主工程归属和所有直接引用仍严格核对。未证明的直接库变化不能自动接受。

新增公开只读的设备描述、连接器和有序父子清单作为编译证据。编译允许的唯一新增结构是已验AM610根 `4102 / 10f4 0002 / 3.5.11.11` 下一个 `HwConfiguratioinDevice`：原生类型 `225bfe47-7336-4dbc-9419-4105a7c831fa`，描述 `40005 / 10F4 0005 / 00.00.00.10`，连接器精确为 `1 / Child / Common.PCI / host_path=-1` 与 `2 / Parent / Inovance:System / host_path=1`。GUID必须新且唯一，没有源码或子树，原兄弟相对顺序不变；不固定索引，不按名称过滤。已存在的派生设备也不得任意移动或换GUID。

依据是[S6b原阶段记录](device-add-visibility.md)及正常控制夹具 `D:\InoPro-S8b-Positive-20261120-091939` 的打开前/编译后原始tree、getter；测试夹具 `tests/fixtures/resident-build-derived-native.json`保留来源路径、SHA-256和树/连接器投影。这个离线投影没有伪造源码或新IDE返回。连接器归属来自所枚举设备，未声称取得对端实际挂接。其他设备、额外节点、缺项、重复、字段变化及原兄弟重排均拒绝。未提供完整设备参数、I/O或最终地址保全审计，也未据此提供设备写入能力。
