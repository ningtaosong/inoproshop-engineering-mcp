# S8b 第一阶段：AM610 离线 I/O 通道与现有映射

**结论②：可读取限定通道，但现有变量映射查询还须限定范围。** 在 InoProShop 1.9.1.6 的一个 AM610 样例上，公开 getter 能按设备、连接器、参数和子元素识别通道，并复查空映射。没有经独立配置证实的非空变量映射正例。本轮只交付探测，产品仍为 0.33.0 候选版、36 项工具。

以上为首轮历史结论。后续在单独准备的夹具中取得一个非空首项及同句柄导出，写后守卫停止了保存。[补充探测和证据边界](io-mapping-positive-probe.md)

## 样例与结果

主文件来自既有交付包 `InoPro-review-20261109-132658.zip` 的 `projects/AM610_Minimal_MCP.project`。固定 SHA-256 为 `89b804a220e213c53ec09f4f38e87b6dd9b68f704c9d063c04535fdbea4a3173`。独立副本的工程位置为 `D:\InoPro-S8b-IO-20261119-204225\engineering\AM610_Minimal_MCP.project`。样例筛查涉及 182 份归档和本机 OEM 示例，未找到足以事先确认 AM610 非空映射表达式的材料。没有为此写入新映射。

遍历了 63 个工程树对象、3 个设备、6 个连接器、30 个参数根和 680 个参数及子元素。仅在 `is_mappable_io` 明确为真时计入通道，余下 654 个元素未计入。已遍历的集合均观察到枚举结束，无分页或截断。26 项来自 `Device/HIGH_SPEED_IO` 连接器 2（`Common.inovance2`）。该数字包含下表两条根及其 24 个成员。

| 参数根、原生方向 | 根类型与位宽 | 离线地址字段 | 直接成员 |
|---|---|---|---|
| 13 · InputData · Input | UINT，16 位 | %IW0 | Bit0 至 Bit15，BOOL，各 1 位；地址 %IX0.0 至 %IX1.7 |
| 14 · OutputData · Output | BYTE，8 位 | %QB0 | Bit0 至 Bit7，BOOL，各 1 位；地址 %QX0.0 至 %QX0.7 |

这里保留 `channel_type` 的原生 Input / Output。所查本机说明未明确这两个值以控制器还是设备为参照。单位均返回空串。26 项的 `automatic_iec_address` 均为真，表中地址来自 `manual_iec_address` getter。同源历史导出里对应的 `IecAddress` 为空，地址没有获得第二种来源的独立确认。参数 50 在设备描述中标为诊断，原导出为 `ChannelType=None, DiagType=Diagnosis`，未计作输入或输出。

## 映射读数及身份

- 通道定位使用设备实例 GUID、连接器 ID、参数 ID 及逐层元素标识。原始记录还保留路径、设备描述身份、连接器接口及其所属设备 GUID。两个参数都有名为 Bit0 的成员，可按上述组合区分。样例根设备身份为 `4102 / 10f4 0002 / 3.5.11.11`，通道所在子设备为 `40600 / 10F4 0600 / 00.00.00.20`。
- 本机公开 `element.io_mapping` 仅暴露首项表达式和状态。26 项均读到 `Id=-1`、`variable=null`、`mapping_creates_variable=false`、`maps_to_existing_variable=true`。安装件表明无首项时也会产生这一组合。同源历史导出的 26 份序列化列表逐项计数均为 0，因此这 26 项可确认未映射。公开 getter 本身没有给出完整映射集合的计数。
- 非空 `variable` 只能作 getter 返回的原始表达式保留。已查接口未返回变量声明的工程对象身份。空字符串、原生 null、首项缺失的组合、字段不可读、枚举中断和完整遍历的零命中分别记录。字段缺失时不根据地址、名称或另一个变量的拼写补值。
- 独立对照使用同主文件指纹的历史原生导出及两份已安装设备描述。按完整通道键逐项比对了 26 个名称、类型和方向；导出只包括四个选中对象。未把序列化的类型模板重复计作成员，也未推断隐藏 OEM、总线或其他工程的通道总数。

## 稳定性与保全

首个进程在同一句柄采集两次，正常关闭并退出后由第二个 IDE 进程独立重开。三份报告一致，但首版 JSON 标量转换拒绝了实际的 `System.Int64`，导致参数 ID、位宽和映射首项 ID 缺失；这些原始错误保留。修正探测脚本后，在同一文件身份及主文件哈希上用第三个进程补采。同句柄两份完整读数一致。前两进程以根元素原生 identifier 和子路径核对同一通道，不能把第三进程的整数写回旧快照。

三个进程均确认正常关闭、退出码 0。主文件的字节与修改时间保持一致。IDE 新建两份 .opt 和一份 .projectbackup；用户级 .opt 内容随打开变化，AllUsers.opt 与备份后续更新了时间，备份内容与主文件相同。探测使用原登记目录和既有租约机制，最终工程与服务租约均已释放。没有启动工程服务或 DSH，没有编译、保存、联机或运行。
